# HeoPress v1.6.2

> 状态 / Status: **已发布 / released**（v1.6.2，2026-11-17）。

[中文](#中文) · [English](#english)

## 中文

### 修复：安装会在第一步就停下

三件事叠在一起，让「照着文档装一遍」在这个网络里根本走不完：

1. **文档的脚本取不到**：`curl raw.githubusercontent.com/...` 在这台机器上是 `000`。现在安装页给了第二条路——用发布页的
   源码包，脚本就在里面，配合 `--source` 还能跳过「下载源码包」这一步。
2. **镜像拉不下来**：安装脚本默认从 `ghcr.io/web-casa` 拉应用镜像，但那里**一个镜像都没发布**。这不是「包是私有的」，
   而是**从来没有推过**——所有人都卡在这一步。现在拉取失败就改为**从同一份源码构建**，日志里会说明；`--build` 仍然表示
   「只构建、不尝试拉取」。
3. **数据库镜像构建需要 GitHub**：`docker/postgres/Dockerfile` 要从 github.com 取 SCWS 与 zhparser。现在两者都可覆盖：

   ```bash
   # 指向镜像站
   docker build -f docker/postgres/Dockerfile -t heopress-postgres:18 \
     --build-arg SCWS_URL=https://mirror.example/scws.tar.gz \
     --build-arg ZHPARSER_URL=https://mirror.example/zhparser.tar.gz docker/postgres
   ```

   或者把 tarball 按 SHA-256 命名放进 `docker/postgres/vendor/`，**完全不联网**也能构建。两种方式都在解包前校验
   SHA-256：镜像站给了不一样的字节，构建会失败而不是进镜像。安装脚本新增 `--db-build-arg` 透传这些值。

### 修复：一个只在 UTC 午夜后一小时爆的测试

站点简报的「今天发布」夹具用 `now - 1h`，在 00:00–01:00 UTC 会落到**前一天**，于是简报统计出 0 篇而断言要 3 篇。改在
**未修改的 main** 上 00:40 UTC 复现（`共 0 篇`），同小时加修复后转绿。夹具现在夹在当天的 UTC 区间内。

### 依赖更新

`i18next` 27、`react-i18next` 18、`jsdom` 31，以及 36 项 minor/patch（`hono` 4.13.18、`astro` 7.4.11、`graphql-yoga`
6.1.0 等）。**`@playwright/test` 保持 1.63.0**：视觉回归作业运行在固定镜像 `mcr.microsoft.com/playwright:v1.63.0-noble`
里，只升 npm 包会让浏览器二进制缺失。

### 升级

```bash
git pull && pnpm install && pnpm build
```

已安装的部署用 `sudo /opt/heopress/heopress-compose pull && up -d` 即可；本次没有数据库迁移。

## English

### Fixed: installation stopped at the first step

Three things together made the documented install impossible on a restricted network:

1. **The script could not be fetched** — `raw.githubusercontent.com` answers `000` there. The install page now documents the
   second route: the release's source archive, which contains the script; `--source` also skips the release download.
2. **The images could not be pulled** — the installer defaulted to `ghcr.io/web-casa`, where **nothing is published**.
   Not "private": never pushed, so this failed for everyone. A failed pull now means **build it from the same source
   tree**, and the log says so; `--build` still means "build, do not try pulling".
3. **The database image needed GitHub** — the Dockerfile fetched SCWS and zhparser from github.com. Both are now
   overridable: `--build-arg SCWS_URL=… ZHPARSER_URL=…` for a mirror, or tarballs named after their SHA-256 dropped into
   `docker/postgres/vendor/` for a build with **no outbound access at all**. Either way the SHA-256 is checked before
   anything is unpacked, so a mirror serving different bytes fails the build instead of reaching the image.
   The installer gained `--db-build-arg` to pass those values through.

### Fixed: a test that only failed in the hour after UTC midnight

The briefing's "published today" fixtures used `now - 1h`, which lands on the **previous** day between 00:00 and 01:00 UTC:
the briefing counted 0 where the assertion expected 3. Reproduced on **unmodified main** at 00:40 UTC (`共 0 篇`) and green
with the fix at the same hour. The fixtures are now clamped into the current UTC day.

### Dependencies

`i18next` 27, `react-i18next` 18, `jsdom` 31 and 36 minor/patch updates (`hono` 4.13.18, `astro` 7.4.11,
`graphql-yoga` 6.1.0, …). **`@playwright/test` stays at 1.63.0**: the visual job runs in the pinned image
`mcr.microsoft.com/playwright:v1.63.0-noble`, and raising only the npm package leaves the browser binaries missing.

### Upgrading

```bash
git pull && pnpm install && pnpm build
```

An existing deployment: `sudo /opt/heopress/heopress-compose pull && up -d`. No database migration in this release.
