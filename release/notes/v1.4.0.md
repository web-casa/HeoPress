# HeoPress v1.4.0

> 状态 / Status: **已发布 / released**（v1.4.0，2026-11-13）。

[中文](#中文) · [English](#english)

## 中文

### 双模型翻译：起草 → 校验 → 修正

翻译不再依赖任何 MT 厂商。内置服务 `heopress:dual-model` 用**两个不同的模型**：

1. **起草**：模型 A 输出严格 JSON，术语表与记忆引用作为约束进去；
2. **机械门禁**（确定性，可穷举测试）：段数与顺序、空段、占位符 `⟦…⟧`、HTML 标签、URL、数字、术语表用词、目标语言≠源语言、
   未翻译文本启发式；
3. **复核**：模型 B 收到原文 + 草稿 + 门禁发现，返回逐段 `ok` / `revise`。**修正文本必须再次通过同一套门禁才被采纳**；
   改坏占位符的修正会被拒绝，保留草稿并标记。

关键取舍：**模型说「没问题」不能凌驾于机械检查**——复核判定 `ok` 但草稿仍违反门禁时，该段标 `unverified`，不算接受。
复核失败时**保留草稿**并标未验证，而不是丢掉已做的工作。

两次调用各自记账、各自定价；选同一个模型两次在**保存时**就被拒绝（否则「校验」是空操作）。

### 翻译任务：可重试、可恢复、不重复付费

翻译现在是一次**持久化任务**（`lumibase_translation_jobs`），按状态与语言对查询，能看到逐段结果：

| 失败类型 | 重试预算 | 下次运行 |
|---|---|---|
| 延后（限流、熔断、日预算） | **不消耗** | 网关给出的 `retryAt` |
| 瞬时（供应商错误、超时） | 消耗一次 | 60 s → 120 s → … 上限 30 分钟 |
| 永久（`BAD_TRANSLATION`、`DUAL_MODEL_*`、`SERVICE_UNAVAILABLE`、校验） | 立即终止 | 原因写进任务行 |

**恢复不重复付费**：调用键是 `translation-job:<id>:a<attempts>:e<epoch>`。worker 崩溃后租约到期重取，attempt 与 epoch 不变，
网关直接重放已记录的草稿/复核答案，不再调用模型；只有操作者显式重试才换 epoch、再付一次。反复死亡的任务以
`EXECUTION_LIMIT` 结束，不会无限重试。

### 站点术语表：规则终于生效

**修了一个真缺陷**：`forbidden` 词条此前**完全不检查**——`rule` 在翻译边界被丢弃，门禁把每条都当成 `prefer`，禁用译法能通过
「验证」。现在三条规则分别执行：`prefer` 要求译法出现、`forbidden` 要求**禁用译法不出现**（新代码 `glossary_forbidden`）、
`do-not-translate` 要求**源词原样保留**。

配套管理面：`/api/v1/glossary` 增删改查（成员读、管理员写、同事务审计、`(站点, 语言对, 词条)` 唯一约束与 `409`），
Studio 侧 `/content/glossary` 页面（中英），规则选择器带说明。

### 修复

全量 CMS 套件在只设置 `DATABASE_URL` 时会出现 2 个文件失败与偶发 hook 超时。根因是 E2E 套件需要的不止数据库（还缺
`JWT_SECRET`，golden-path 还缺 `HEOPRESS_RUNTIME=docker`），却只 guard 了数据库——现在按自身前提跳过并说明该设什么；
数据库重的 `beforeEach` 也不再撞上 10 秒默认超时。

## English

### Two-model translation: draft → verify → revise

Translation no longer depends on an MT vendor. The built-in `heopress:dual-model` service uses **two different models**:

1. **Draft** — model A answers strict JSON with the glossary and memory references as constraints;
2. **Mechanical gates** (deterministic, exhaustively testable) — segment count and order, empty segments, placeholders, HTML
   tags, URLs, numbers, glossary renderings, target ≠ source, and an untranslated-text heuristic;
3. **Review** — model B receives source + draft + gate findings and answers per segment `ok` or `revise`. **A revision is
   accepted only if it passes the same gates**, so a revision that breaks a placeholder is rejected and the draft is kept.

The trade-off that matters: **a model saying "fine" does not overrule a mechanical check**. When the reviewer says `ok` but the
draft still violates a gate, the segment is marked `unverified`, not accepted. When the reviewer fails, the draft is kept and
marked unverified rather than thrown away.

Both calls are ledgered and priced separately; choosing the same model twice is refused **at save time**, because that would
make the verification a no-op.

### Translation jobs: retryable, recoverable, and never paid twice

A translation is now a durable job (`lumibase_translation_jobs`) you can list by status and locale, with per-segment results:

| failure | retry budget | next run |
|---|---|---|
| deferred (throttling, open breaker, daily budget) | **not consumed** | the gateway's `retryAt` |
| transient (provider error, timeout) | one attempt | 60 s → 120 s → … capped at 30 min |
| permanent (`BAD_TRANSLATION`, `DUAL_MODEL_*`, `SERVICE_UNAVAILABLE`, validation) | stops | the code is a column, not a log line |

**Recovery does not pay twice.** The call key is `translation-job:<id>:a<attempts>:e<epoch>`: after a worker crash the lease
expires, the job is picked up with the same attempt and epoch, and the gateway replays the recorded draft and review answers
instead of calling the models again. Only an explicit operator retry bumps the epoch and pays once more. A job that keeps dying
ends with `EXECUTION_LIMIT` rather than retrying forever.

### Site glossary: the rules finally apply

A real defect: `forbidden` entries were **not checked at all** — the `rule` column was dropped at the translation boundary, so
every entry was treated as `prefer` and a banned rendering could pass verification. The three rules now mean what they say:
`prefer` requires the rendering, `forbidden` requires the banned rendering to be **absent** (new code `glossary_forbidden`),
`do-not-translate` requires the **source spelling to survive**.

Managing them: `/api/v1/glossary` CRUD (member read, admin write, audit in the same transaction, a unique constraint on
site/pair/term with a `409`), and a `/content/glossary` screen in the Studio with the rule selector and its help text.

### Fixed

The full CMS suite failed two files and intermittently timed out a hook when only `DATABASE_URL` was set. E2E suites need more
than a database (`JWT_SECRET`, and `HEOPRESS_RUNTIME=docker` for the golden path) but guarded only on the database; they now
skip on their own missing prerequisites and say which variables to set, and a database-heavy `beforeEach` no longer races the
10-second default.
