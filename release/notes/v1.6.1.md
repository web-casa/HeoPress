# HeoPress v1.6.1

> 状态 / Status: **已发布 / released**（v1.6.1，2026-11-15）。

[中文](#中文) · [English](#english)

## 中文

### 修复：gVisor 下的构建沙箱起不来

v1.6.0 把 gVisor 描述成「一行配置」。实测之后发现不是：**gVisor 拒绝任何携带 SELinux 标签的安全上下文**
（`SELinux is not supported: system_u:system_r:container_t:s0:…`），而在 AlmaLinux/Rocky/RHEL 上，上一版为了写产物
给挂载加上了 `:z` 标签——两者正好冲突。

现在选择 `HEOPRESS_ASTRO_BUILD_RUNTIME=runsc` 时：

- 计划自动改用 `--security-opt label=disable`，并去掉挂载上的 `:z`（关了标签再重贴标签没有意义）；
- **`no-new-privileges` 保留**——关闭标签不能顺带削弱硬化，这一点有测试钉住；
- 不选 gVisor 的部署行为完全不变。

### 实测数据（AlmaLinux 10 + Podman 5.8，同一套参数、同一镜像）

| 检查 | crun（默认） | gVisor (runsc) |
|---|---|---|
| 写 `/out` | ✅ | ✅ |
| 写 `/in`（只读） | 拒绝 | 拒绝 |
| 缓存 tmpfs | ✅ | ✅ |
| 容器内 `fetch()` | 退出 9 | 退出 9 |
| 单条命令耗时 | 195 ms | 225 ms（+15%） |

### 用 gVisor 之前必须知道的三件事

1. **不接受 SELinux 标签**——本版已自动处理；
2. **rootless 下无法启动**：`systemd error: Interactive authentication required`；改用 `--cgroup-manager=cgroupfs` 则报
   `open /sys/fs/cgroup/cgroup.subtree_control: permission denied`。要用 gVisor 需要 **rootful 运行时**，或给用户 slice
   做真正的 cgroup 委派（我们在测试 VM 上尝试 `user@.service` 的 `Delegate=yes` 未生效）。**默认的 A 档（rootless + crun）
   不受影响**；
3. **必须连同边车安装**：单拷 `runsc` 会报 `sidecar "gvisor_sentry" not usable`，要把 `gvisor-bin/` 一起装到同一目录。

### 升级

```bash
# 只是拿到修复，不需要改任何配置
git pull && pnpm install && pnpm build
```

使用 A 档（默认）的部署无需任何动作；使用 B 档的部署升级后即可正常启动。

## English

### Fixed: the build sandbox could not start under gVisor

v1.6.0 described gVisor as "one configuration away". Measurement said otherwise: **gVisor refuses any security context that
carries a SELinux label** (`SELinux is not supported: system_u:system_r:container_t:s0:…`), while on AlmaLinux/Rocky/RHEL the
previous release added `:z` to the mounts so the build could write its output — the two collide.

With `HEOPRESS_ASTRO_BUILD_RUNTIME=runsc` the plan now:

- passes `--security-opt label=disable` and drops `:z` from the mounts (relabelling is pointless once labels are off);
- **keeps `no-new-privileges`** — turning labels off must not quietly weaken hardening, and a test pins that down;
- changes nothing for deployments that do not select gVisor.

### Measured (AlmaLinux 10 + Podman 5.8, same arguments, same image)

| check | crun | gVisor |
|---|---|---|
| write `/out` | ✅ | ✅ |
| write `/in` (read-only) | denied | denied |
| cache tmpfs | ✅ | ✅ |
| `fetch()` in container | exit 9 | exit 9 |
| one trivial command | 195 ms | 225 ms (+15%) |

### Three things to know before using gVisor

1. **It accepts no SELinux label** — handled by this release;
2. **It does not start under a rootless runtime**: `systemd error: Interactive authentication required`, and
   `--cgroup-manager=cgroupfs` fails on `cgroup.subtree_control`. gVisor needs a **rootful** runtime or real cgroup delegation
   for the user slice (a `Delegate=yes` drop-in for `user@.service` did not take effect on our test VM). The default tier A
   (rootless + crun) is unaffected;
3. **Install it with its sidecars**: a lone `runsc` binary dies on `sidecar "gvisor_sentry" not usable`; `gvisor-bin/` must sit
   beside it.

### Upgrading

```bash
git pull && pnpm install && pnpm build
```

Tier A deployments need no action; a tier B deployment starts working again after the upgrade.
