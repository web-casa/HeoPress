# HeoPress v1.6.4

> 状态 / Status: **已发布 / released**（v1.6.4，2026-11-18）。

[中文](#中文) · [English](#english)

## 中文

### 卡住的拉取不再让安装无限等待

v1.6.3 让安装优先拉取发布镜像，第一次真实端到端安装就暴露了另一半问题：**`docker pull` 自己没有超时**。

那一次安装停在 `ghcr.io/web-casa/heopress-cms:1.6.3` 上 **15 分钟**——没有进度、磁盘也不增长——而注册表本身是通的
（`ghcr.io/v2` 1.2 秒返回 401，`pkg-containers.githubusercontent.com` 0.4 秒返回 400）。瞬时卡住就把安装一直吊在那里，
而安装器本来就有「拉不到就构建」的回退。

现在每个决定「拉还是建」的拉取都在 `timeout` 下运行：

- 默认 **300 秒**，用 `HEOPRESS_PULL_TIMEOUT` 可以改；
- 超时 = 不可用 → 走源码构建；
- 覆盖应用镜像、数据库镜像、显式 `--db-image` 与 Caddy 镜像；
- 系统没有 `timeout`（util-linux）时按原样运行，不会因此拒绝安装。

### 验证

同一个 VM 上，把注册表指向一个不可路由的地址、并把超时设为 15 秒：

```
[heopress-install] pulling 10.255.255.1:5000/x:1 (up to 15s)
[heopress-install] 10.255.255.1:5000/x:1 is not available from the registry; building it from /root/hp164 instead
```

**正常网络下行为不变**——同一次会话里用真实注册表跑完整安装：拉取 `heopress-cms`（526 MB）、`heopress-site-classic`、
`heopress-postgres`，五个服务全部 healthy，**0 次构建**。

### 升级

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

本次只改了安装脚本，没有代码改动，也没有数据库迁移。

## English

### A hanging pull no longer stalls the install

v1.6.3 made an install pull the published images first, and the first real end-to-end run found the other half of that
path: **`docker pull` has no timeout of its own**.

That run sat on `ghcr.io/web-casa/heopress-cms:1.6.3` for **15 minutes** — no progress, no disk growth — while the
registry itself answered in 1.2 s (`ghcr.io/v2` → 401, `pkg-containers.githubusercontent.com` → 400). A transiently
stalled pull left the installer waiting forever, even though it already knows how to fall back to building.

Every pull that decides between "use the image" and "build it" now runs under `timeout`:

- **300 seconds** by default, `HEOPRESS_PULL_TIMEOUT` to override;
- running out of time means "unavailable" → build from the source tree;
- applied to the app images, the database image, an explicit `--db-image` and the Caddy image;
- on a system without `timeout` (util-linux) the pull runs unmodified rather than the install refusing to start.

### Verified

Same guest, registry pointed at an unroutable address, timeout lowered to 15 s:

```
[heopress-install] pulling 10.255.255.1:5000/x:1 (up to 15s)
[heopress-install] 10.255.255.1:5000/x:1 is not available from the registry; building it from /root/hp164 instead
```

**On a healthy network nothing changes** — in the same session a real install pulled `heopress-cms` (526 MB),
`heopress-site-classic` and `heopress-postgres`, and every service came up healthy with **zero builds**.

### Upgrading

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

Only the installer changed: no code changes and no database migration.
