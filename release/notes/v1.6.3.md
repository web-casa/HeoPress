# HeoPress v1.6.3

> 状态 / Status: **已发布 / released**（v1.6.3，2026-11-18）。

[中文](#中文) · [English](#english)

## 中文

### 安装不再需要自己编译数据库

v1.6.2 让安装在拉不到镜像时改从源码构建——能装成，但数据库镜像要编译 PostgreSQL 18 + pgvector + zhparser，其中 SCWS
与 zhparser 还得从 github.com 取，受限网络里根本走不通。

这一版把镜像**发布出来**：打发布标签时构建并推送三个镜像到 GHCR，覆盖 amd64 与 arm64。

| 镜像 | 内容 |
|---|---|
| `ghcr.io/web-casa/heopress-cms` | API + Studio |
| `ghcr.io/web-casa/heopress-site-classic` | 渲染服务 |
| `ghcr.io/web-casa/heopress-postgres` | PostgreSQL 18 + pgvector + zhparser |

标签是不带 `v` 的版本号（`v1.6.3` → `1.6.3`），`latest` 只在正式发布标签时移动——重发补丁不会偷偷变成 `latest`。

`docker/install.sh` 现在**优先拉取**数据库镜像，拉取失败才回到本地构建。所以：

- 能访问 GHCR：拉镜像 + 起服务，几分钟装完；
- 不能访问：行为和 v1.6.2 一样，从源码构建（或在镜像站 / `vendor/` 的配合下构建）。

### 一条发布纪律

GHCR 新建的包默认**私有**。所以工作流的最后一步是**匿名拉取每一个标签**，拉不到就失败——发布不能声称提供了安装方
取不到的镜像。如果这一步红了，说明包还需要一次手动切换（package settings → Change visibility → Public），
在 `docs/en/deployment/docker.md` 里有说明。

### 升级

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

本次没有代码改动，也没有数据库迁移。

## English

### Installing no longer compiles the database

v1.6.2 made an install fall back to building from source when a pull failed. That worked, but the database image builds
PostgreSQL 18 + pgvector + zhparser, and SCWS and zhparser come from github.com — which is exactly what a restricted
network cannot reach.

This release **publishes the images**: a release tag builds and pushes three of them to GHCR, for amd64 and arm64.

| image | contents |
| --- | --- |
| `ghcr.io/web-casa/heopress-cms` | API + Studio |
| `ghcr.io/web-casa/heopress-site-classic` | the rendering service |
| `ghcr.io/web-casa/heopress-postgres` | PostgreSQL 18 + pgvector + zhparser |

Tags are the version without its leading `v` (`v1.6.3` → `1.6.3`); `latest` moves only on a plain release tag, so
re-publishing a patch cannot silently become `latest`.

`docker/install.sh` now **pulls the database image first** and builds it only when the pull fails. So:

- with GHCR reachable: pull and start, minutes;
- without it: the v1.6.2 behaviour, building from source (or building with a mirror / `vendor/`).

### A release rule

A new GHCR package is **private** by default, so the workflow ends by pulling every tag **anonymously** and fails when
that fails — a release must not claim images an installer cannot fetch. If that step goes red, the package needs a
one-time visibility flip (package settings → Change visibility → Public), documented in
`docs/en/deployment/docker.md`.

### Upgrading

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

No code changes and no database migration in this release.
