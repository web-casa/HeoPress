# HeoPress v1.6.5

> 状态 / Status: **已发布 / released**（v1.6.5，2026-11-19）。

[中文](#中文) · [English](#english)

## 中文

### 相对于 v1.6.4 没有代码改动

这一版发布的是**流水线本身**：镜像发布不再无条件重建，同时还补了「怎么检查一次发布真的发布了什么」的部署文档。
已经装在 v1.6.4 上的实例不需要升级。

### 镜像发布：内容不变就不重建

此前每个发布标签都会把三个镜像在 amd64 与 arm64 上重新构建一遍，约十三分钟。v1.6.4 就是个例子——它只改了安装脚本、
发布说明和版本号，产物和 v1.6.3 逐字节相同。

现在发布时先比较：

- **不重建**：只改了文档、发布记录、安全扫描配置、工作流、工具脚本、安装脚本、或只有 `"version"` 变动的 `package.json`；
  此时把上一版的 manifest 复制到新标签（内容寻址，不构建），`latest` 按同样规则移动。
- **重建**：代码、锁文件、依赖、Dockerfile、数据库镜像有变化。

两种情况最后都会跑一遍**匿名拉取校验**——复用出来的标签取不到，与构建失败一样会让流水线变红，不会静默发出装不上的版本。

### 检查一次发布发布了什么

部署文档新增三条命令：确认标签是多架构的、确认不带凭据也能拉、确认数据库镜像里真的有 `vector` 与 `zhparser`。

### 升级

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

本次没有代码改动，也没有数据库迁移；不升级也不影响运行。

## English

### No code changes since v1.6.4

This release publishes the **pipeline change**: image publishing no longer rebuilds unconditionally, and the deployment
docs now say how to check what a release actually published. An installation on v1.6.4 has nothing to upgrade for.

### Images: no rebuild when the contents cannot change

Every release tag used to rebuild all three images on amd64 and arm64, about thirteen minutes. v1.6.4 is the example —
it changed the installer, the release notes and version strings, and produced bytes identical to v1.6.3.

A release now compares first:

- **no rebuild** when only documentation, release records, the scanner configuration, workflows, tooling scripts, the
  installer, or a `package.json` whose only edit is `"version"` changed — the previous release's manifests are copied to
  the new tag (content-addressed, no build) and `latest` moves under the same rule;
- **rebuild** when code, the lockfile, a dependency, a Dockerfile or the database image changed.

Both paths end with the **anonymous pull check**: a reused tag that cannot be fetched turns the pipeline red exactly
like a broken build, so a release cannot claim images an installer cannot pull.

### Checking a release's images

The deployment docs gained three commands: the tag is multi-architecture, it pulls without credentials, and the database
image really contains `vector` and `zhparser`.

### Upgrading

```bash
sudo /opt/heopress/heopress-compose pull && sudo /opt/heopress/heopress-compose up -d
```

No code changes and no database migration; not upgrading changes nothing.
