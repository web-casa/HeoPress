# HeoPress v1.5.0

> 状态 / Status: **已发布 / released**（v1.5.0，2026-11-14）。

[中文](#中文) · [English](#english)

## 中文

### 静态目录挂载：存档站与新文章同源共存

运营者常有一批**永远不会变成条目**的静态页面——网页存档复原、脚本生成的文档镜像。删掉可惜，转成条目又不值得。
现在可以给站点挂载一个目录：

- HeoPress 路由不到的路径由它提供；**条目、插件路由、`robots.txt`、`sitemap*`、`.well-known`、`health`、`admin`、
  feed、`llms.txt` 永远优先**——静态文件不能遮蔽系统路径，这条每一类都有测试；
- 目录必须在 `HEOPRESS_STATIC_ROOT` 之下，`realpath` 仍在根内，**符号链接不跟随**；路径先按 `/` 切段再解码两次，
  拒绝穿越、反斜杠、NUL、控制字符与隐藏条目（`.git`、`.env` 不会因为挂载变成公开文件）；
- 响应头按类型给：HTML `max-age=0, must-revalidate`，资源 `immutable`，其余 300 秒；`ETag`/`Last-Modified`/304 齐全；
- `static-urls.txt` 里的 URL 合并进站点 sitemap；Astro 构建把目录并入产物；
- **不改写运营者的 HTML**：canonical 与 noindex 原样透传。

### 纠错插件：公开表单 → 审核 → 文章上的更正记录

`heopress-corrections` 是新的官方插件：

1. **公开表单**：宿主校验来源（站点批准域名）、8 KiB 上限、每地址 5 次/分钟；蜜罐字段被填时**给出与人完全相同的中性回答**并丢弃；
   **从不解析目标页面是否存在**——表单不是探测工具；
2. **审核**：在 Studio 里改报告状态即审核队列，无需第二套界面；
3. **接受后**：生成一条更正记录，并按站点设置把 `<aside data-heopress-correction="…">` 追加到文章正文——**幂等**：
   同一报告只会有一个块，运营者手改过的块不会被重写或重复；关闭设置则只保留记录；
4. **门禁**：正文里的更正块若指向不存在或未发布的记录，**拒绝发布**；
5. **公开与隐私**：`/corrections` 列出已发布的更正；更正页输出 `CorrectionComment` 结构化数据。举报者的姓名与邮箱
   属个人数据，**不出现在任何公开路由、响应、sitemap 或日志**里。

**一处诚实的能力边界**：文章页上的 `correction` 结构化数据目前**做不到**——SDK 还不能向别人的页面贡献 Schema
（backlog 里「核心 Schema 贡献」仍是待补契约）。我们只在更正自己的页面上输出节点，并把这个限制写进文档。

### 插件打包矩阵：每个官方插件都在 CI 里打包并加载

此前打包验收只覆盖术语表插件，新插件的「打包后独立安装」靠手工验证——纠错插件就是这样发布的。
`scripts/verify-plugin-packages.mjs` 现在对**每个** `packages/plugin-*`：打包 → 用 `npm --offline` 装进仓库外的干净项目
（只允许 SDK 一个依赖）→ 加载并调用默认导出，校验**注册的每个扩展点都在 manifest 声明内**。不需要数据库与服务器。

### 修复

镜像运行时验收报告「服务在数据库中断期间重启」时只有一行结论。现在会打印前后 `StartedAt`/`RestartCount`、退出码、
是否被 OOM 终止以及该服务最后 40 行日志。我们本地用真实停库 50 秒**没能**复现该崩溃（worker 按设计存活），所以不做
「这是 flake」的结论——只保证下一次可诊断。

## English

### A static directory beside your content

Operators often have pages that will never become entries — a web-archive restore, a generated documentation mirror. Deleting
them is a loss; turning them into entries is not worth it. A site can now mount a directory:

- paths no HeoPress route claims are served from it, and **entries, plugin routes, `robots.txt`, `sitemap*`, `.well-known`,
  `health`, `admin`, feeds and `llms.txt` always win** — a static file can never shadow a system path, with a test per class;
- the directory must sit under `HEOPRESS_STATIC_ROOT` and its `realpath` must stay inside it, **symlinks are never followed**,
  and the path is split before it is decoded (twice), refusing traversal, backslashes, NUL, control characters and hidden
  entries (a mounted `.git` or `.env` never becomes public);
- headers by kind: HTML `max-age=0, must-revalidate`, assets `immutable`, other `300`; `ETag`, `Last-Modified` and `304`;
- the URLs a `static-urls.txt` declares are merged into the sitemap, and an Astro build ships the directory in its artifact;
- **your HTML is not rewritten**: canonicals and `noindex` pass through.

### The corrections plugin: a public form, moderation, and a record on the article

`heopress-corrections` is the new official plugin:

1. **A public form** — the host verifies the request's origin, 8 KiB, 5 requests per minute per address; a filled honeypot gets
   **the same neutral answer a person gets** and is dropped; the endpoint **never resolves the target page**, so it cannot be used
   to probe what exists;
2. **moderation** is the report's status in the Studio — no second UI;
3. **on accept** exactly one correction record is created and, if the site enables it, one
   `<aside data-heopress-correction="…">` block is appended to the article body — **idempotent**: one block per report, and a block
   an operator edited is never rewritten or duplicated; with the setting off the record stays collection-only;
4. **a gate check** refuses to publish an article whose block points at a missing or unpublished record;
5. **public and private**: `/corrections` lists published corrections and their pages carry `CorrectionComment` structured data.
   A reporter's name and email are personal data and never appear in a public route, response, sitemap or log line.

**One honest boundary**: a `correction` node on the *article* page is not possible yet — the SDK cannot contribute Schema to
another plugin's page (the backlog's "core schema contribution" is still an open contract). We emit the node on the correction's
own page and say so in the docs.

### Every official plugin is now packed and loaded in CI

Packed-install verification used to cover only the glossary plugin, so a new plugin was packed by hand — the corrections plugin
shipped that way. `scripts/verify-plugin-packages.mjs` now packs **every** `packages/plugin-*`, installs it into a clean project
outside the repository with `npm --offline` (the SDK may be its only dependency) and calls its default export, checking that
**every extension point it registers is declared by its manifest**. No database, no server.

### Fixed

The image acceptance check used to report "a service restarted during the database outage" and nothing else. It now prints the
before/after `StartedAt` and restart count, the exit code, whether the container was OOM-killed, and the last 40 log lines. We
could not reproduce the crash locally with a real 50-second database outage (the worker stayed up by design), so this does not
claim it was a flake — it makes the next occurrence diagnosable.
