# HeoPress v1.2.0

> 状态 / Status: **已发布 / released**（v1.2.0，2026-11-11）。

[中文](#中文) · [English](#english)

## 中文

v1.2.0 把 v1.0.0 之后计划的两个版本（v1.1 与 v1.2）的能力一次交付，并补上对外开放开发所需的贡献入口。

### 内容生产与运营

- **WordPress 导入**：WXR 文件或 REST 接口两条输入路径，文章 / 页面 / 分类 / 标签 / 作者 / 媒体、SEO 插件字段映射、
  `?p=` 旧链接重定向、预演报告，以及 `heopress import wordpress` 命令行。
- **翻译待办**：按「缺失 / 过期 / 待审」分栏的队列，可从缺失项直接创建译文。
- **简报式改写**：先生成结构化简报（论点、读者、角度、有序分节与依据来源、语气、字数、SEO），校验通过后再成文；
  不符合契约时修复一次，仍失败则明确失败，不反复烧调用。
- **时效标记、自动陈旧判定与复核提醒**：人工标记带来源、截止日与审核队列；每小时扫描把长期未更新的已发布内容标为
  「自动陈旧」，内容被编辑后自动撤销；每天把到期的条目汇总提醒**真正有权处理它的人**。

### 简报与对外发布

- **官方简报插件**：概览里的「今天 / 本周」分节、一键生成可编辑的简报草稿，并声明自己的集合与 `/briefing` 路由。
- **集合 feed**：站点 feed 的集合可配置，插件的集合自动获得 `/feed/<集合>.xml`。

### 机器可读与分发

- **Markdown 内容协商**：同一 URL 在 `Accept` 偏好 Markdown 时返回 Markdown（默认关闭），带 `Vary: Accept`、
  `noindex` 与 canonical `Link`，缓存按表示分键。
- **静态站边缘协商**：Cloudflare Pages（Pages Function）、Vercel、Caddy 按各自能力实现同一语义，Netlify 如实标注不支持；
  另提供可在 CI 运行的回放器验证「给定路径与 `Accept`，边缘发哪个文件」。

### 扩展

- **翻译服务扩展点**（第十一个）：插件可注册翻译实现，按字符计费进入既有账本与预算，选中但不可用时明确失败，不静默回退。
- **DeepL 官方插件**：分段批量翻译、语言映射、术语表镜像（按词条哈希建/复用/更新）与类型化错误。
- **插件密钥存储**：按站点 / 插件 / 名称加密保存，密文与作用域绑定，接口只返回名称与是否已配置，运营者在 Studio 内配置。

### 对外贡献

- `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md` 与中文版贡献指南；工具链与实际一致（Node 24、pnpm 9.12）。

## English

v1.2.0 delivers what v1.1 and v1.2 planned after v1.0.0 in one release, and adds the entry points the project needs
before outside contributors can take part.

### Producing and running content

- **WordPress import** — WXR files or the REST API, with posts, pages, categories, tags, authors and media, SEO-plugin
  field mapping, `?p=` redirects, a dry-run report, and `heopress import wordpress`.
- **Translation backlog** — a queue split into missing, stale and awaiting review, with drafts created from the
  missing column.
- **Briefing-style rewrite** — a structured brief first (thesis, audience, angle, ordered sections with their sources,
  tone, length, SEO), validated before anything is written; one repair on a contract violation, then a typed failure
  rather than repeated model calls.
- **Timeliness marks, automatic staleness and review reminders** — a manual mark with a source, a due date and a
  review queue; an hourly pass marks long-untouched published items as automatically stale and clears itself when the
  item is edited; a daily digest reminds the people who can actually act when a deadline arrives.

### Briefing and publishing

- **Official briefing plugin** — today and this-week sections in the overview, one-click editable briefing drafts, and
  its own collection with `/briefing` routes.
- **Collection feeds** — the site feed's collection is configurable, and a plugin's collection gets `/feed/<name>.xml`.

### Machine-readable output

- **Markdown negotiation** — the same URL answers Markdown when `Accept` prefers it (off by default), with
  `Vary: Accept`, `noindex` and a canonical `Link`, and a cache keyed by representation.
- **Static-target negotiation** — Cloudflare Pages (a Pages Function), Vercel and Caddy each implement the same
  semantics in what they actually support, Netlify says it does not, and a replay harness proves in CI which file the
  edge would serve for a given path and `Accept`.

### Extensions

- **Translation-service extension point** (the eleventh) — a plugin registers a translation implementation, billed by
  characters through the existing ledger and budget; a selected-but-unavailable service fails loudly instead of
  falling back silently.
- **Official DeepL plugin** — batched translation, locale mapping, a glossary mirror keyed by the term list's hash,
  and typed failures.
- **Plugin secrets** — encrypted per site, plugin and name, bound to that scope, with the API returning names and
  configured state only; operators configure them in Studio.

### Contributing

- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` and a Chinese contributing guide, with the toolchain the code actually
  requires (Node 24, pnpm 9.12).
