# HeoPress v1.3.1

## 中文

### 修正：Netlify 的 Markdown 协商实际是「受限」

v1.3.0 把能力矩阵里 Netlify 的 `markdown-negotiation` 标为 `yes`，注里写着「前提：部署打包 Edge Functions」。
**这个前提本仓库的部署路径满足不了**：Netlify 适配器走 Deploy API 的文件摘要上传，只上传普通文件，从不发送
`edge_functions`；经它部署的站点不会注册生成的函数，协商不会生效。

Netlify 的公开 API 文档只文档化了**服务端函数**的上传（`required_functions`），Edge Functions 的部署方式是
**Git 连续部署**或 **CLI 12.2.8 及以上**的手动部署。所以这不是配置写法的问题，也不是我们能从这条路径绕过的。

现在矩阵是 `degraded`，中英两份部署文档都写明：只有由**会打包它的部署方式**发布时才生效。生成物本身没有变化；
变的是不再声称这条路径能交付它。

### 补齐与门禁

- `docs/en/publishing/frontend-deployments.md` 与 `git-snapshots.md`：运维部署必读的两篇此前只有中文，现在补齐英文版。
- 中英文档一致性门禁接进 `pnpm check:all`：冻结现有 190 篇单边文档与 3 对允许的漂移；新增单边文档、或基线过期
  （文档补了对应语言却没更新基线）都会失败。它不需要 git 历史，因此镜像 CI 里也能跑。

### 产品行为

**没有变化**：没有一行运行站点的代码被改动。这一版是文档与工具的修正。

## English

### Corrected: Markdown negotiation on Netlify is *degraded*, not supported

v1.3.0 marked Netlify's `markdown-negotiation` as `yes`, with a note reading "the deploy must bundle Edge Functions".
**This deploy path cannot meet that precondition**: the Netlify adapter posts a file digest to the Deploy API, which
uploads ordinary files only and never sends `edge_functions`, so a site deployed by it never registers the generated
function and nothing negotiates.

Netlify's public API documentation covers serverless function uploads (`required_functions`) only; Edge Functions are
deployed by Git continuous deployment or a manual deploy with CLI 12.2.8 or later. So this is not a configuration we got
wrong, and not something this path can work around.

The matrix now says `degraded`, and both deployment pages state that the function only takes effect when the deploy is
one that bundles it. The generated artifacts are unchanged; what changed is that we no longer claim this path delivers it.

### Added and enforced

- `docs/en/publishing/frontend-deployments.md` and `git-snapshots.md`: the two deployment pages operators need had no
  English version.
- The zh-CN/en parity gate is now part of `pnpm check:all`: the 190 existing single-sided docs and 3 known drifting pairs
  are frozen in a committed baseline, and a new single-sided doc — or a stale baseline entry after someone pays debt —
  fails the build. It needs no git history, so it runs in the mirror too.

### Product behaviour

**Unchanged**: no code that runs a site was touched. This release is a documentation and tooling correction.
