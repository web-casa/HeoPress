# HeoPress v1.2.1

> 状态 / Status: **已发布 / released**（v1.2.1，2026-11-11）。

[中文](#中文) · [English](#english)

## 中文

补丁版本，**产品行为无变化**。它把私有主分支上的两件事带到公开仓库：

- **CLA 检查**：`.github/cla-signatures.json` 记录每份 CLA 接受（登录名、姓名、日期、CLA 版本），
  `scripts/cla-check.mjs` 判定「已签 / 未签 / 机器人跳过」，`.github/workflows/cla.yml` 在每个 PR 上运行。
  未签的 PR 无法合并；格式错误或缺失的签名文件视为失败，而不是「空名单放行所有人」。
- **发布记录**：v1.2.0 的私有提交与公开提交对应关系进入私有账本（不随导出发布）。

贡献流程见 `CONTRIBUTING.md`：阅读 `CLA.md` → 在 PR 下评论「I have read and agree to the HeoPress CLA.」→
维护者把接受记录进签名文件 → 检查通过后即可合并。

## English

A patch release, **no product behaviour changes**. It publishes two things from the private main branch:

- **The CLA check** — `.github/cla-signatures.json` records each acceptance (login, name, date, CLA version),
  `scripts/cla-check.mjs` decides signed / unsigned / skipped-for-a-bot, and `.github/workflows/cla.yml` runs it on
  every pull request. An unsigned pull request cannot merge, and a missing or malformed signatures file fails rather
  than admitting everyone.
- **The release record** of v1.2.0 (private commit → public commit), which stays in the private ledger.

The flow is in `CONTRIBUTING.md`: read `CLA.md`, comment "I have read and agree to the HeoPress CLA." on the pull
request, a maintainer records it in the signatures file, and the check passes.
