# 审计与问题处置

HeoPress P07a 任务 10.1–10.5（规格 `seo/audit-triage`、`studio/audit-workspace`；审计规则来自 P07 的 `seo/site-audit`）。
在 Studio 一级导航“审计”中打开；旧地址 `设置 › Site audit` 与 `设置 › Links` 会跳转到这里。

## 视图

- **未处理**：当前站点的全部未忽略问题，按严重程度（错误、警告、提示）排序；只列出你能读取其中至少一个页面的问题，仅管理员可见的问题只对管理员显示。
- **按规则**：链接（失效链接、失效锚点）、重复元数据（标题、描述、canonical）、hreflang 回链、结构化数据、Markdown 副本。
- **已忽略**：显示原因、操作人与到期时间，可以恢复。到期后自动回到未处理。
- **已解决**：一次完整（未被截断）的审计不再发现的问题，保留 90 天，显示规则、标题、你能读取的受影响页面与解决时间。
- 二级面板显示上次审计的时间与结果（已完成、失败、因问题过多被截断——此时清单不完整），管理员可点“重新审计”。

## 处置

- **忽略**（仅站点管理员，不接受 API Key）：可写原因，期限 30 / 90 / 180 / 365 天，默认 90 天。忽略后会出现约 8 秒的“撤销”提示；撤销会把问题放回原位置。
  忽略与恢复都写入站点审计日志（`audit_issue_ignored`、`audit_issue_restored`），可在“日志与监控”中查到。
- 忽略以问题指纹为准：同一问题在后续审计中再次出现时仍是已忽略；问题修好后进入已解决并清除忽略；之后若再次出现，回到未处理。
- 被截断的审计不会删除、解决或清除任何问题——没有扫描到的部分保持原样。

## 修复入口

- **失效站内链接**：在详情中“为旧地址添加重定向”，填入新地址后先“检查”——系统用重定向导入的试运行给出修改前后对比（旧地址现在 404，之后 301 到新地址）、
  指向该旧地址的页面数，以及冲突（该地址仍是页面）或循环；确认后才添加。下一次审计后问题进入已解决。
- 其他问题：在详情中“在编辑器打开”受影响页面直接修改。
