# 日志与监控

HeoPress P07a 任务 11.1–11.8（规格 `ops/event-log`、`studio/monitoring`）。只对当前站点的站点管理员显示；旧的“活动记录”“可达性”“Mission Control”迁入此模块。

## 状态卡片

- **站点组**：可达性（最近一次体检）、站点审计与链接扫描（最近一次运行的结果与时间）。
- **实例组**（仅引导管理员）：数据库、迁移、扩展、缓存、检索、存储、队列的健康检查（与 `/health` 相同的检查，服务端直接调用）与最近 24 小时失败的后台任务数。
- 卡片只显示最近一次检查的时间；取不到结果（例如健康检查超时）显示“未知”，不会显示为正常。
- 点击“可达性”“站点审计与链接扫描”“后台任务”卡片会把事件流过滤到对应的运行事件，查询框显示对应条件；再次点击取消。

## 事件流

| 来源 | 内容 | 时间取自 |
|---|---|---|
| 内容 | 条目的创建、修改、删除；提交审核、批准、退回（提交与决定是两条事件） | 变更事件时间；提交为创建时间，决定为决定时间 |
| 运行 | 审计、链接扫描、可达性在每个站点的最终状态（成功、失败、中断） | 审计日志时间 |
| 安全、成员与权限、API 密钥 | 登录、角色与策略变更、成员加入与移出、密钥操作等 | 审计日志时间 |
| 实例（仅引导管理员） | 每次定时任务执行的结果（成功、失败及原因、未完成、因上一次未结束而跳过）、账户启用与停用 | 系统事件时间 |

- 事件内容在服务端脱敏：不含 IP、User-Agent、令牌；密钥只显示末 4 位。
- 级别：全部、警告及以上、错误、成功，各带数量；数量不受级别过滤影响，但随来源、关键词变化。直方图显示最近 60 分钟每分钟的事件数，错误单独标出。
- 查询框匹配消息、事件名与对象；用 `|` 表示“或”，例如 `site-audit|link-scan`。
- 默认每 5 秒自动显示新事件；暂停后新事件不插入（显示待显示的数量），继续后按时间补入，选中的事件保持选中。
- 读取新事件时服务端回看 60 秒、客户端按事件 ID 去重，晚提交的事务不会丢也不会重复。
- 二级面板显示事件可查询的最早时间；系统事件保留 90 天，超出部分由每日清除任务删除。

## 已保存的筛选

- 在二级面板为当前过滤条件起名保存，按用户保存（`users.preferences.studio.savedFilters`），最多 20 条，在其他浏览器登录后同样可用。

## 排查建议

1. 卡片为“异常”：点击卡片查看对应的运行事件，选中错误事件查看完整字段（可复制），再用“打开审计”“查看可达性”进入对应页面。
2. 实例组“后台任务”有失败：在实例来源中搜索 `scheduled_job_failed`，事件的 `reason` 与各站状态数量说明了失败原因与范围。
3. 找不到早于某个时间的事件：查看面板中的“事件保留自”，更早的事件已按保留策略清除（见 `docs/en/operations/data-retention.md`）。
