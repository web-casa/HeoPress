# studio/review-workspace Specification

## Purpose
审稿工作台把待审核、定时、已发布与草稿稿件集中在“列表 + 详情”中，让编辑不离开页面即可看到稿件概要、发布前检查与处理记录，并完成批准或退回；审核权限在服务端判定。

## Requirements

### Requirement: 稿件视图与筛选
“内容”模块 SHALL 提供收件箱（需要我处理的稿件：我有权审核的待审稿件、被退回给我的稿件）、我的稿件、待审核、定时发布、已发布、草稿视图，每个视图显示数量；
列表 SHALL 可按集合、作者、语言筛选并按标题搜索，显示标题、作者、状态、发布前检查是否全部通过与最近更新时间。视图与筛选 SHALL 反映在页面地址中，刷新或分享地址后保持一致。
列表只包含用户有权读取的集合中的稿件。

#### Scenario: 刷新保持筛选
- **WHEN** 用户在“待审核”视图按作者“陈默”筛选后刷新页面
- **THEN** 仍是待审核视图且只显示陈默的稿件

### Requirement: 审核权限在服务端判定
权限模型 SHALL 新增按集合授予的“审核”权限；站点管理员拥有全部权限因而包含审核，其他角色默认没有，需要管理员授予（升级前任何成员都能批准，升级说明中写明这一变化）。
列出待审稿件、批准与退回 SHALL 由服务端按用户在该集合上是否拥有审核权限判定，而不只是站点成员身份：没有审核权限的用户调用批准或退回 MUST 返回 403，且稿件状态不变；
待审列表 MUST 只包含调用者有权审核的稿件。批准与退回 MUST 只接受交互式 Studio 会话：API Key 与 Agent（含 MCP 工具）的请求 MUST 返回 403，与其被授予的权限范围无关
（ADR-0012：审批渠道与 Agent 渠道隔离），MCP 中的批准与退回工具同样返回 403；提交审核仍可由 Agent 发起。起草者能否批准自己的稿件沿用集合现有的“要求由他人审核”设置；ADR-0012 的单人 / 团队模式不在本 change 实现。
界面中的按钮状态只是这些判定的反映。

#### Scenario: 没有审核权限的作者直接调用接口
- **WHEN** 没有审核权限的作者绕过界面，直接请求批准自己提交的稿件
- **THEN** 返回 403，稿件仍为待审核

#### Scenario: 管理员范围的 API Key
- **WHEN** 使用一个具有管理员权限范围的 API Key，或经 MCP 工具，请求批准一篇待审稿件
- **THEN** 返回 403，并说明批准需要人工在 Studio 中进行

#### Scenario: 作者查看待审稿件
- **WHEN** 没有审核权限的作者打开待审核视图中自己提交的稿件
- **THEN** 批准与退回按钮不可用，并提示“需要管理员或已获得审核权限的角色审核”

### Requirement: 稿件详情与发布前检查
选中一篇稿件时，详情区 SHALL 显示标题、摘要、属性（状态、作者、篇幅、计划发布时间、收录设置）、正文预览、处理记录，以及发布前检查：
SEO 标题与描述长度、收录设置、结构化数据是否有效、正文中指向本站的链接是否指向存在且已发布的页面、图片是否缺少替代文本。
指向其他网站的链接在本 change 中一律标为“未检查”（尚无外部链接检查的数据来源）；检查 MUST NOT 在请求中访问外部地址。每项检查 SHALL 给出结果与原因；
检查结果只作提示，是否阻止发布 MUST 与该站点现行的发布规则一致，不得因本界面而放宽或收紧。

#### Scenario: 指向不存在的本站页面
- **WHEN** 待审稿件正文中有一个指向本站已下线页面的链接
- **THEN** “正文链接”检查未通过并列出该链接；批准按钮写为“仍然批准”

#### Scenario: 外部链接
- **WHEN** 正文中有一个外部链接
- **THEN** 该链接标为“未检查”，检查不发起任何外部请求

### Requirement: 发布前检查的读取权限
发布前检查的结果 SHALL 只返回给有权读取该条目的用户，并遵守字段级读取限制：用户无权读取的字段 MUST NOT 参与检查结果的展示（显示为“无权查看”），
无权读取条目时与条目不存在返回相同结果。

#### Scenario: 受限字段
- **WHEN** 用户可读取文章但无权读取其 SEO 描述字段
- **THEN** 描述长度检查显示“无权查看”，响应中不含描述内容

### Requirement: 批准、发布与退回
有审核权限的用户 SHALL 能在详情区批准稿件（稿件进入“已批准”）或退回（必须填写退回原因）；没有审核权限时这两个操作不可用并说明原因。
对已批准的稿件，详情区 SHALL 提供“发布”与“按计划发布”（需要发布权限，沿用现有的发布与定时规则）。详情区 SHALL 另提供“批准并发布”，依次执行批准与发布：
批准成功而发布失败时，稿件 MUST 停留在已批准，界面说明发布失败的原因，MUST NOT 显示为已发布。操作完成后列表 SHALL 自动选中下一篇待处理稿件。

#### Scenario: 批准并发布时发布失败
- **WHEN** 有审核与发布权限的成员对一篇稿件选择“批准并发布”，批准成功但发布因路由冲突被拒绝
- **THEN** 稿件状态为已批准，界面显示发布失败的原因与“重试发布”

#### Scenario: 退回
- **WHEN** 有审核权限的成员选择“退回修改”并填写原因“补充数据来源”
- **THEN** 稿件回到作者的草稿，原因记录在处理记录中并对作者可见，列表选中下一篇

### Requirement: 键盘审稿
在列表中 SHALL 能用 J / K 切换稿件、用 ⌘↵（Ctrl+Enter）批准当前稿件；批准前若有未通过的检查，快捷键 MUST 先显示未通过项并要求再次确认。

#### Scenario: 有未通过检查时快捷批准
- **WHEN** 当前稿件有 1 项检查未通过，用户按 ⌘↵
- **THEN** 显示未通过的检查与“仍然批准”确认，用户确认后才批准；发布仍需另外操作
