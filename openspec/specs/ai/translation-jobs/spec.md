# ai/translation-jobs Specification

## Purpose
让翻译成为**持久任务**：站点创建任务后，翻译服务失败、被限流、预算顺延或 worker 重启都不会让工作消失；
任务记录状态、逐段结果、失败原因与重试预算，运营者可以查询、重试与取消，而重复执行不会重复付费。

## Requirements

### Requirement: 站点作用域的持久翻译任务

系统 SHALL 为站点保存翻译任务，记录源语言、目标语言、请求的段落、状态、业务重试次数、下一次可运行时间、
最近错误码、逐段结果、计数器、实际执行的服务与模型标识，以及创建、开始、结束与更新时间。
任务状态 MUST 只是 `queued`、`running`、`succeeded`、`failed`、`cancelled` 之一。
任务 MUST 属于创建它的站点；站点 MUST 来自请求上下文，MUST NOT 来自请求体。
任务的重试次数 MUST 只统计**业务重试**：因限流、熔断或每日预算造成的延后 MUST NOT 增加它。

#### Scenario: 创建任务
- **WHEN** 站点管理员为 `en → zh-CN` 提交两个段落
- **THEN** 返回 `201` 与一个 `queued` 的任务，段落被原样保存，业务重试次数为 0

#### Scenario: 站点隔离
- **WHEN** 站点 B 的管理员用站点 A 的任务 id 读取、重试或取消
- **THEN** 两个站点之间互不可见：对方得到 `404`，且 A 的任务状态与内容不变

#### Scenario: 校验拒绝
- **WHEN** 请求缺少段落、段落 id 重复、段落文本为空或超过翻译上限，或目标语言与源语言相同
- **THEN** 返回 `400`，不创建任务，也不入队

### Requirement: 已注册的队列与消费者

任务 SHALL 在事务提交后进入名为 `translation-jobs` 的队列；该队列 MUST 在队列登记表中登记，
worker MUST 为它注册消费者。入队失败 MUST NOT 回滚已创建的任务：任务表是持久凭据，周期清扫会在之后重新入队。
同一个任务的消息重复投递 MUST NOT 造成两次并发执行。

#### Scenario: 入队与消费
- **WHEN** 任务创建成功
- **THEN** 一条携带站点与任务 id 的消息进入 `translation-jobs`，且 worker 注册了该队列的消费者

#### Scenario: 重复消息
- **WHEN** 同一个任务的两条运行消息同时到达
- **THEN** 只有一个执行取得租约并运行，另一个不产生任何翻译调用

### Requirement: 租约、续租与崩溃恢复

消费者 MUST 以租约认领到期任务，并在运行期间续租；租约 MUST 大于一次翻译（含双模型两次调用）的最长执行时间。
worker 在运行中死亡或部署重启后，租约过期 MUST 使任务被重新认领并继续，MUST NOT 丢失工作。
同一次业务尝试的所有执行 MUST 使用同一个账本调用标识，使已经完成的阶段被重放而不是重新付费。
恢复 MUST NOT 增加业务重试次数；崩溃后的重新认领次数 SHALL 有硬上限（普通执行、重试与延后的认领不计入），
达到上限的任务 MUST 以明确的错误码结束。

#### Scenario: 崩溃后恢复
- **WHEN** 一次执行在草稿与复核都已完成后、写回任务之前进程退出，租约过期后任务被重新认领
- **THEN** 任务以同样的逐段结果成功结束，起草与复核两个阶段在账本里各只有一条调用记录

#### Scenario: 执行上限
- **WHEN** 任务因反复崩溃被认领到上限次数仍未完成
- **THEN** 任务以 `failed` 结束，错误码为 `EXECUTION_LIMIT`，不会继续入队

### Requirement: 尊重成本控制的重试策略

系统 SHALL 按失败类型决定任务的下一次状态：瞬时失败（提供方错误、超时、网络、链路耗尽）MUST 消耗一次业务重试
并按指数退避重新排队；因限流、熔断或每日预算被网关延后的任务 MUST 按网关给出的可运行时间重新排队且**不消耗**业务重试；
永久失败（翻译质量不合法、服务不可用、双模型未配置或两个模型相同、请求校验、预算已耗尽、能力不支持）
MUST 立即结束为 `failed`。业务重试用尽的任务 MUST 结束为 `failed`，MUST NOT 继续入队。
每次失败、延后与取消的原因 MUST 写入任务的错误码字段，MUST NOT 只存在于日志。

#### Scenario: 瞬时失败
- **WHEN** 提供方返回 500，任务还有业务重试预算
- **THEN** 任务回到 `queued`，业务重试次数加一，下一次可运行时间晚于当前时间，错误码记录提供方错误

#### Scenario: 延后不消耗重试
- **WHEN** 网关因限流抛出带可运行时间的延后错误
- **THEN** 任务回到 `queued`，业务重试次数保持不变，下一次可运行时间等于网关给出的时间

#### Scenario: 重试预算用尽
- **WHEN** 连续瞬时失败达到业务重试上限
- **THEN** 任务为 `failed`，记录最后一次错误码，且不再入队

#### Scenario: 永久失败
- **WHEN** 翻译服务以 `BAD_TRANSLATION`、`SERVICE_UNAVAILABLE` 或双模型配置错误失败
- **THEN** 任务立即为 `failed`，业务重试次数不增加，记录该错误码，且不再入队

### Requirement: 逐段结果与未复核的可见性

任务成功时 SHALL 写入逐段结果：每段的最终文本、状态（`verified`、`revised`、`rejected_verification`、
`unverified`，或单模型/插件路径的 `translated`）、门禁代码与复核理由（若有）。
计数器 SHALL 记录已翻译、已修订、未复核与被复核拒绝的段落数；双模型服务执行时 SHALL 记录起草与复核的模型标识。
复核失败或没有产生结论时，任务 MUST 保留草稿文本、把段落标为 `unverified`，MUST NOT 把任务记为失败，
也 MUST NOT 静默丢弃该段落。

#### Scenario: 复核失败
- **WHEN** 复核调用失败，草稿仍然可用
- **THEN** 任务为 `succeeded`，所有段落有译文且状态为 `unverified`，未复核计数等于段落数

#### Scenario: 修订被拒
- **WHEN** 复核给出一个未通过机械门禁的修订
- **THEN** 该段保留草稿文本，状态为 `rejected_verification`，被拒计数加一

### Requirement: 操作者接口、审计与取消

系统 SHALL 提供任务的创建、分页列表（按状态与目标语言过滤）、详情、重试与取消接口。
读取 MUST 对站点成员开放，创建、重试与取消 MUST 只对站点管理员开放。每次创建、重试与取消 MUST 写一条站点审计，
且 MUST NOT 在审计里保存译文正文。取消 MUST 对 `queued` 与 `running` 生效：任务立即为 `cancelled`，
运行中的执行 MUST 在下一个续租周期停止调用；已经结束的任务 MUST 拒绝取消。
显式重试 MUST 只适用于 `failed` 与 `cancelled`，SHALL 重置业务重试预算与认领次数，并使用新的账本调用标识，
使重试真的重新翻译而不是重放上一次的答案。

#### Scenario: 成员只读
- **WHEN** 站点的普通成员列出或读取任务
- **THEN** 请求成功；该成员创建、重试或取消任务时得到 `403`

#### Scenario: 取消运行中的任务
- **WHEN** 管理员取消一个 `running` 的任务
- **THEN** 任务立即为 `cancelled`，之后该执行的结算 MUST NOT 把状态改回成功或失败

#### Scenario: 操作者重试
- **WHEN** 管理员重试一个 `failed` 的任务
- **THEN** 任务回到 `queued`，业务重试次数归零，新的执行使用与之前不同的账本调用标识

#### Scenario: 不可取消
- **WHEN** 管理员取消一个已经 `succeeded` 或 `failed` 的任务
- **THEN** 返回 `409`，任务状态不变
