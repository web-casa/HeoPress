# sites/site-switching Specification

## Purpose
让同时属于多个站点的人在 Studio 中切换当前站点，而不重新登录；切换后界面、请求与会话只属于新站点，旧站点的迟到响应、缓存与实时消息不会出现在新站点的界面中。站点之间的授权边界不因切换而放宽。

## Requirements

### Requirement: 我的站点列表
已登录的人 SHALL 能取得自己可进入 Studio 的站点列表（站点标识、名称、在该站点的角色、是否为当前站点、是否要求 MFA）。是否可进入 MUST 按该站点的有效权限（角色或策略授予的 Studio 访问及其条件）判定，与登录、刷新、换发使用同一判定；引导管理员包含全部站点。API Key、前台会话 MUST 不能取得该列表。

#### Scenario: 属于两个站点的人
- **WHEN** 一个人是站点 A 的编辑、站点 B 的只读成员，请求自己的站点列表
- **THEN** 列表包含 A 与 B 及各自角色，不包含其他站点

#### Scenario: 仅凭策略获准进入 Studio
- **WHEN** 一个人在站点 B 的角色本身不允许进入 Studio，但其策略授予了 Studio 访问
- **THEN** 列表包含 B；切换到 B 并刷新会话后仍是 Studio 会话

#### Scenario: API Key 请求站点列表
- **WHEN** 使用站点 A 的 API Key 请求站点列表
- **THEN** 返回 403

### Requirement: 换发目标站点会话
系统 SHALL 允许用当前站点的有效 Studio 会话，为同一次登录换发本人可进入的另一站点的会话：新会话只携带目标站点的权限，访问令牌与刷新令牌只对目标站点有效，认证时间与 MFA 状态沿用原登录。以口令登录得到的会话换发时 MUST 出示当前站点未撤销的刷新令牌；Cloudflare Access 会话无需换发，改变请求的站点即可；外部签发方的会话不支持切换。目标站点不可进入、站点不存在、用户被禁用或会话已失效时 MUST 拒绝，且前两种情况的响应相同；目标站点要求 MFA 而原登录未经 MFA 时 MUST 拒绝并要求在目标站点登录。换发 MUST 计入审计并按用户限速。

#### Scenario: 切换到成员站点
- **WHEN** 站点 A 的编辑（同时是站点 B 的只读成员）请求切换到 B
- **THEN** 得到只对 B 有效的会话，在 B 只能读取，不能修改

#### Scenario: 切换到非成员站点
- **WHEN** 只属于站点 A 的人请求切换到站点 B，或切换到不存在的站点
- **THEN** 两种情况返回相同的 403，不签发任何令牌

#### Scenario: 引导管理员
- **WHEN** 引导管理员在站点 A，切换到自己没有成员关系的站点 B
- **THEN** 得到 B 的 Studio 会话

#### Scenario: 已退出的会话
- **WHEN** 已在站点 A 退出（刷新令牌已撤销）后，用尚未过期的访问令牌请求切换
- **THEN** 返回 401，不签发令牌

### Requirement: 登录会话统一撤销
由同一次登录换发出的各站点会话 SHALL 属于同一个登录会话。退出、任一站点刷新令牌的重用检测 MUST 使该登录会话在所有站点的刷新令牌与访问令牌立即失效；"退出所有设备"与修改或重置密码 MUST 使该用户全部登录会话失效；刷新与换发 MUST 拒绝修改密码之前签发的刷新令牌，且撤销与换发并发时不得签发出仍然有效的令牌。升级到本版本前签发的刷新令牌 MUST 失效（需重新登录一次）。

#### Scenario: 在 A 修改密码
- **WHEN** 已从 A 切换到 B 后，在 A 修改密码，再用 B 的旧刷新令牌刷新
- **THEN** 刷新被拒绝，B 的会话失效

#### Scenario: 换发与退出同时发生
- **WHEN** 从 A 换发到 C 的同时，在 B（同一登录）退出
- **THEN** 要么换发失败，要么换发出的 C 会话随登录会话一起失效：C 的刷新令牌与访问令牌都不能再使用

#### Scenario: A 的刷新令牌被重放
- **WHEN** A 的一个已轮换的刷新令牌被再次出示
- **THEN** A 与由同一登录换发的 B 的令牌链全部被撤销

### Requirement: 切换不串站
Studio 切换站点后 SHALL 只显示新站点的数据：切换前发出、切换后才返回的请求结果、旧站点的缓存、通知、在线状态与实时消息 MUST 不出现在新站点的界面中。切换时仍在保存的修改，界面 SHALL 先等待其结果；超时仍未返回时 MUST 如实说明结果未知，不得说成已完成或在新站点重放。同一浏览器的不同标签页 SHALL 各自保持自己的当前站点，一个标签页切换不改变另一个标签页的站点与会话；同一站点的多个标签页刷新会话 MUST 不互相作废。

#### Scenario: 旧站点的迟到响应
- **WHEN** 在站点 A 打开内容列表、请求尚未返回时切换到站点 B，随后 A 的响应才到达
- **THEN** 界面只显示 B 的内容，A 的数据不出现

#### Scenario: 两个标签页
- **WHEN** 标签页 1 与标签页 2 都在站点 A，标签页 1 切换到站点 B
- **THEN** 标签页 2 仍在站点 A，其请求仍发往 A 且会话有效

#### Scenario: 切换时仍在保存
- **WHEN** 在站点 A 保存一篇文章、请求尚未返回时选择切换到 B
- **THEN** 先等待保存结果；超时仍未返回时提示 A 的修改结果未知并由用户确认是否继续；不显示"已保存"，不在 B 重做该修改

#### Scenario: 同一站点两个标签页同时刷新
- **WHEN** 两个标签页都在站点 A，访问令牌同时过期并同时刷新
- **THEN** 两个标签页都继续可用，没有因重用检测被登出

#### Scenario: 同一用户的两次独立登录
- **WHEN** 同一用户在标签页 1 以登录会话 S1 使用站点 A、在标签页 2 以另一次登录 S2 使用站点 B，标签页 1 切换到 B
- **THEN** 标签页 2 仍使用 S2 的 B 会话，退出 S1 不影响标签页 2

#### Scenario: 切换失败
- **WHEN** 切换时换发被拒绝（例如目标站点要求 MFA），或用户在"结果未知"提示中选择不继续
- **THEN** 留在原站点，切换期间被挂起的请求照常完成

### Requirement: 跨站只读概要是唯一的跨站读取
会话只携带当前站点权限的约定不变；唯一的例外是 `studio/network-summary` 定义的跨站只读概要。该例外 SHALL 只返回该能力列出的站点标识、名称、主域名（可为空）与主域名状态、调用者本人在该站点的角色与聚合字段（计数、合计、时长、状态与统计时间），
MUST NOT 返回任何站点的条目、正文、成员、设置或其他可识别记录；每个站点的每一项 MUST 在该站点的行级安全上下文中、按该用户在该站点的有效权限单独判定；要求二次验证的站点在当前登录未经二次验证时 MUST NOT 返回其数据。
概要只能由交互式 Studio 会话读取（经过 Studio 访问检查，含应用访问权与二次验证要求），API Key、前台会话与外部签发方会话 MUST 被拒绝。每次读取 SHALL 写入一条审计记录（用户、时间、返回的站点数量，不含各站数据），并按用户限速。
除该概要外，以站点 A 的会话请求站点 B 的任何资源 MUST 仍被拒绝。

#### Scenario: 概要不含记录
- **WHEN** 站点 A 的成员读取跨站概要，其中包含站点 B
- **THEN** 响应只含 B 的标识、名称、主域名与主域名状态、本人在 B 的角色、计数、合计、状态与统计时间，不含 B 的任何条目标题、路径或成员信息

#### Scenario: 其他跨站请求仍被拒绝
- **WHEN** 用站点 A 的会话请求站点 B 的审计问题列表
- **THEN** 返回与无权限相同的拒绝结果

#### Scenario: 读取被审计
- **WHEN** 用户读取一次跨站概要
- **THEN** 审计日志新增一条记录，含用户与站点数量，不含各站的数字
