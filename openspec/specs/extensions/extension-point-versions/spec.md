# extensions/extension-point-versions Specification

## Purpose
让插件与 HeoPress 的兼容性按扩展点判断：每个扩展点与插件宿主 API 都有独立的契约版本，只有真正受影响的扩展点在破坏性变更后停止生效，插件作者能准确知道要升级什么。

## Requirements

### Requirement: 扩展点契约版本
十个扩展点（`collections`、`routes`、`source-adapters`、`gate-checks`、`jobs`、`endpoints`、`events`、`admin-panels`、
`build-steps`、`briefing-sections`）与插件宿主 API SHALL 各有独立的契约版本号（语义化版本），由 Extension SDK 公布，
并与 HeoPress 在运行时检查使用的版本一致。
某个扩展点的破坏性变更 SHALL 只提升该扩展点的主版本，不改变其他扩展点的版本。发布说明 SHALL 列出每个版本变化的扩展点。

#### Scenario: 只有一个扩展点变更
- **WHEN** 新版本只对事件扩展点做了破坏性变更
- **THEN** 只有事件扩展点的主版本提升；只使用任务与端点扩展点的插件仍然兼容

#### Scenario: 新增的扩展点有独立版本
- **WHEN** 实例新增一个扩展点（例如 v1.1 的 `briefing-sections`）
- **THEN** 只有该扩展点出现在版本表中（`1.0.0`），既有扩展点的版本不变，既有的插件清单仍然有效

### Requirement: 清单声明扩展点版本范围
插件清单 SHALL 为它申请的每个扩展点能力与宿主 API 声明兼容的版本范围。申请了扩展点能力却没有声明该扩展点版本范围、
或声明了未申请的扩展点版本范围的清单 MUST 被视为无效并给出原因。官方迁移工具 SHALL 能为现有清单补上当前版本的范围。

#### Scenario: 缺少扩展点版本范围
- **WHEN** 清单申请了 `ext:events` 但没有声明事件扩展点的版本范围
- **THEN** 清单校验失败，并指出缺少的扩展点

#### Scenario: 用迁移工具补全
- **WHEN** 插件作者对一个只有整体 HeoPress 版本范围的清单运行官方迁移工具
- **THEN** 清单为它申请的每个扩展点与宿主 API 补上当前版本的范围，并能通过校验

### Requirement: 各环节检查扩展点版本
安装、升级与批准 SHALL 检查清单中每个扩展点的范围是否包含当前版本，不包含时 MUST 拒绝，并指出扩展点、要求的范围与当前版本。
插件加载时 SHALL 再次检查：实例升级后不再兼容的扩展点 MUST NOT 生效，并在后台标记该插件需要升级；同一插件中仍兼容的扩展点照常生效。
声明了发布前钩子的插件，其事件扩展点不兼容时 SHALL 按无法询问处理，即拒绝这些钩子覆盖的集合的发布，直到插件升级或停用。

#### Scenario: 安装不兼容的插件
- **WHEN** 管理员安装一个声明事件扩展点范围为 `^2.0.0` 的插件，而当前事件扩展点版本为 1.0.0
- **THEN** 安装被拒绝，原因指出事件扩展点要求 `^2.0.0`、当前为 1.0.0

#### Scenario: 实例升级后部分不兼容
- **WHEN** 实例升级使任务扩展点主版本提升，一个已安装插件同时使用任务与端点扩展点
- **THEN** 该插件的任务不再运行并被标记需要升级，它的端点继续服务

#### Scenario: 发布前钩子所在扩展点不兼容
- **WHEN** 一个声明了发布前钩子的插件，其事件扩展点在实例升级后不再兼容
- **THEN** 这些钩子覆盖的集合的发布被拒绝，原因指出该插件需要升级
