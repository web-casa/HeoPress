# extensions/pipeline-extensions Specification

## Purpose
门禁检查判断的是「这份草稿与站点其他内容是否一致」，因此它需要读到其他内容；此前它只能看草稿本身。
本变更把门禁检查的条目访问补成与作业、订阅一致的能力受限访问。

## Requirements

### Requirement: 门禁检查的站点范围条目访问

`gate-checks` 点的插件 SHALL 获得与作业、订阅相同的站点范围条目访问：只能读写自己声明的
`items:<access>:<collection>` 能力覆盖的集合，只能触达该站点的数据，其他站点的条目 MUST 视为不存在；
Hold、发布守卫、能力拒绝审计与门禁本身 MUST 照常生效。其他扩展点（来源适配器、构建步骤）MUST NOT 因此
获得条目访问。插件没有声明某个集合的读取能力时，读取该集合 MUST 被拒绝并记一次能力拒绝审计。

#### Scenario: 声明后可以读取

- **WHEN** 一个声明了 `ext:gate-checks` 与 `items:read:<集合>` 的插件的门禁检查读取本站点该集合的条目
- **THEN** 读取成功，返回本站点该集合的条目

#### Scenario: 未声明被拒绝

- **WHEN** 同一插件的门禁检查读取一个它没有声明读取能力的集合
- **THEN** 读取被拒绝，产生一次能力拒绝审计，检查得到可判定的失败而不是本站点的数据

#### Scenario: 跨站点不可见

- **WHEN** 门禁检查读取另一个站点的同名条目
- **THEN** 该条目视为不存在

#### Scenario: 其他扩展点不获得该访问

- **WHEN** 同一插件在来源适配器或构建步骤里读取条目
- **THEN** 读取被拒绝：只有门禁检查点获得条目访问
